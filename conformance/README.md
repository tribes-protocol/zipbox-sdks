# SDK conformance suite

One set of fixtures, four SDKs. Every SDK (`sdks/typescript`, `sdks/python`, `sdks/go`,
`sdks/rust`) runs every file in `fixtures/` against a local mock server in its own test
suite. A fixture that one SDK passes and another fails is a bug in the failing SDK.

The wire contract itself is `packages/public-api-contract/openapi.json` (served at
`https://zipbox.ai/openapi.json`). These fixtures pin the client behaviour that an
OpenAPI document cannot: token caching, 401 recovery, retries, path resolution, SSE
collection and error mapping.

## Fixture shape

```json
{
  "name": "exec_streams_and_collects",
  "description": "…",
  "call": { "op": "sandbox.exec", "args": { "id": "sbx_1", "cmd": "…" } },
  "exchanges": [{ "request": { … }, "response": { … } }],
  "expect": { "result": { … } } // or { "error": { "code": "…", "status": 404 } }
}
```

- `call.op` is an SDK-agnostic operation name (table below). The runner maps it to the
  SDK's own method and passes `args` in that language's idiom.
- `exchanges` are served **in order**. The mock server fails the test when a request
  arrives that does not match the next exchange, and when the call finishes with
  exchanges left unserved.
- `expect.result` is a **subset** match against the SDK's return value converted to
  JSON (camelCase keys; a Python/Go/Rust runner converts its own field names). `null`
  means the call returns nothing. `{"length": n, "items": [...]}` matches a list: its
  length, and each item as a subset at the same index. `{"text": "…"}` matches a
  string or bytes result decoded as UTF-8.
- `expect.error` is a subset match against the raised error: `code` (the public
  error code), `status` (HTTP status, when there was one), `requestId`, `docsUrl`,
  `retryable`.

### Matching a request

| Field      | Rule                                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `method`   | Exact.                                                                                                                                |
| `path`     | Path plus query string, exact. Query parameters are percent-encoded (`/` → `%2F`).                                                    |
| `headers`  | Each listed header must be present (names lower-case) with this value. `{{ANY}}` = any non-empty value. Unlisted headers are ignored. |
| `body`     | JSON body, deep-equal after parsing. Absent = not checked.                                                                            |
| `bodyText` | Raw body, exact string. Absent = not checked.                                                                                         |

Inside `body`, the string `{{ANY}}` matches any non-null value at that position. It stands in for
values a client generates fresh on every call, such as a sealed envelope.

### Serving a response

`status`, optional `headers`, and either `body` (serialized as JSON with
`content-type: application/json`) or `bodyText` (sent verbatim, with the listed
`content-type`).

### Placeholders

| Placeholder | Replaced with                                                                                                                                                                                                                           |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{{BASE}}`  | The mock server's origin, e.g. `http://127.0.0.1:43123`. Control plane and box are the same server: box routes (`/exec`, `/files`, …) and control-plane routes (`/sandbox`, `/account`, `/billing`) never collide.                      |
| `{{HOST}}`  | The hostname of `{{BASE}}` (no port).                                                                                                                                                                                                   |
| `{{ANY}}`   | Header matching only: any non-empty value.                                                                                                                                                                                              |
| `{{SAME}}`  | Header matching only: the same non-empty value this header carried on the fixture's previous request (a retry that must reuse its `Idempotency-Key`).                                                                                   |
| `{{DEAD}}`  | An origin no box answers on, e.g. `http://127.0.0.1:43124`: a port the runner bound and closed before the fixture runs, so every dial is refused and the request never leaves the client. Stands in for a box `baseUrl` that has moved. |

Runners construct the client with `apiKey = "zb_" + "T" * 43` and
`baseUrl = {{BASE}}`, with retry backoff and create polling shortened so the suite runs
in milliseconds (the delays are configuration, never skipped logic).

## Client rules every SDK implements

1. **Auth.** `Authorization: Bearer <apiKey>` on the control plane; the key comes from
   the constructor or `ZIPBOX_API_KEY`. The control plane URL comes from the
   constructor, `ZIPBOX_API_URL`, or the default `https://api.tribes.xyz`.
2. **Box token.** Fetched from `GET /sandbox/:id` on first use of a box, cached per box
   id for the client's lifetime. A box answering 401 re-fetches the detail **once** and
   retries the request once; a second 401 raises `unauthorized` with `retryable: true`
   (a deleted key fails the re-fetch itself, at the control plane, so this one is a live
   key the box has not received yet). A box whose detail is not `ready` raises
   `box_not_running` without calling the box. A box's `baseUrl` is not permanent: a
   created box answers on its boot address first and moves once, to `box--<name>`. A box
   request that fails before anything was sent (refused or failed connect, DNS, a TLS
   handshake that fails or ends early) waits one rung of the unsent ladder (base 500 ms,
   factor 2, cap 30 s, jitter), drops the cached box, runs the rule 11 wait, and retries on
   the `baseUrl` and token that wait returned, with no attempt ceiling. The wait's verdict
   ends it: `paused`, `start_failed`, `deleting` and `gone` raise the wait's own error. The
   ladder grows across these re-reads and resets only when the box answers a request.
3. **Errors.** A body shaped `{error: {code, …}}` is the envelope: raise its `code`,
   `message`, `requestId`, `retryable`, `retryAfterMs`, `docsUrl`. Any other non-2xx
   (box routes answer `{error: "<message>"}`) maps by status: 400/413/422
   `invalid_request`, 401 `unauthorized`, 402 `insufficient_credits`, 403 `forbidden`,
   404 `not_found`, 409 `conflict`, 429 `rate_limited`, 502 `box_not_running`, other
   5xx `unavailable`. `docsUrl` is always `https://zipbox.ai/docs/errors#<code>`.
4. **Retries.** One rule: an error whose `retryable` is true is retried on GET requests
   and on `create` and `fork` (each carries one `Idempotency-Key` per call, reused on
   every retry), up to `maxRetries` (default 3). By code, `rate_limited`, `unavailable`
   and `box_not_running` are retryable; the envelope's own `retryable` overrides that,
   and a code the SDK does not know maps by status. The delay is `Retry-After` when the
   response has one, else the envelope's `retryAfterMs`, else exponential backoff with
   jitter. Nothing else is retried, except a request that was never sent: a control-plane
   request retries it in place on the unsent ladder, a box request re-reads the box first
   (rule 2). A follower (`commands.events`) and a wait (rule 11) never retry sooner than
   that hint either.
5. **Exit codes are results.** `exec` returns a non-zero `exitCode`; it never raises for it.
6. **Paths.** A path that does not start with `/` is joined to `/root/workspace`.
7. **No timeouts by default.** No SDK sets a request or exec deadline unless the caller
   passes one. A box runs until someone stops it.
8. **PTY reconnect.** A PTY socket that drops reconnects with exponential backoff
   (cap 30 s, jitter) and no attempt ceiling; the ladder resets only when a frame is
   received. It re-attaches the same session id with the same `clientId` and `resume=1`.
   The first connection waits on the same ladder while the box gives no answer (a failed
   connect, TLS handshake or upgrade) or still answers 401 after the token re-read
   succeeded (a live key the box has not received yet). A dial that is refused or fails
   before the upgrade drops the cached box and re-reads it with the rule 11 wait before the
   next attempt, so a PTY follows a box whose `baseUrl` moved. A PTY ends only on an
   answered verdict: the control plane refusing the key, or the box or session gone.
9. **Box envelopes.** A credential the box consumes (a Tailscale auth key) is sealed on the
   caller's machine to the box's `agentPublicKey` and never sent in the clear. The scheme is
   P-256 ECDH → HKDF-SHA256 (empty salt, `info` = `zipbox-tailscale-v1|<sandbox id>`, 32 bytes)
   → AES-256-GCM (12-byte iv, ciphertext with the 16-byte tag appended), every field base64url
   without padding. The key is read with `GET /sandbox/:id` right before sealing (a claim
   re-mints it); a box without one, or not `provisioning`/`running`, raises `box_not_running`
   without a request. A `409 box_key_changed` re-reads the key and re-seals **once**. The auth
   key is never logged, never stored, and never part of an error message.
10. **Private boxes.** `create` with `private: true` returns once the box is `running` with an
    `agentPublicKey`; it is not `ready` until it joins a tailnet. A box-direct call on a box whose
    row says `privateMode: true` first probes `GET <baseUrl>/challenge` with a 5 s deadline. Any
    HTTP answer counts as reachable, and so does a failed TLS handshake (the box answered; its
    certificate is what is missing, and the box call itself waits that out); success is cached
    per box. A connection that was never made within the deadline raises
    `box_private_unreachable` instead of hanging. Lifecycle calls go to the control plane and
    always work.
11. **Readiness.** A wait (`create`, `getOrCreate`, `waitReady`, `fork`, `resume`, and `pause`
    for `paused`) reads `readiness` from `GET /sandbox/:id/wait?until=ready|paused`. The server
    holds that request until the box reaches `until`, cannot reach it by itself, or the
    server's hold limit passes, and always answers the box's detail; a held answer that is
    still `settling` is asked again at once, with no deadline. For `ready`: `ready` returns;
    `awaits_tailnet` returns (rule 10); `paused` raises `box_not_running`, `start_failed`
    raises `start_failed`, and `deleting` and `gone` raise `conflict`, all with
    `retryable: false`. For `paused`: `paused` returns; anything but `settling` raises
    `conflict`, `retryable: false`. A read that fails with a retryable error waits on the poll
    backoff (1 s growing by 1.25× to 10 s, with jitter) and never ends the wait. A `404` from
    `/wait` is an API that predates it: the wait reads `GET /sandbox/:id` once; a `404` there
    raises `not_found`, a `200` falls back to re-reading `GET /sandbox/:id` on the poll
    backoff with the same verdicts. Public statuses are `provisioning`, `running`, `stopping`,
    `paused`, `deleting` and `destroyed`. A row
    without `readiness` (an older control plane) falls back to the rule before it: `ready`
    returns, a private box running with its key returns, `destroyed` and
    `deleting` raise `conflict`, anything else keeps reading. A box call on a
    detail that is not `ready` raises `tailnet_not_connected` (`retryable: false`) for
    `awaits_tailnet`, else `box_not_running`, retryable only when `readiness` is `settling`
    (without `readiness`: only while `provisioning` or `running`). Every lifecycle call drops
    the box's cached token; a detail that is `ready` (a lifecycle answer, a `/wait` answer, a
    create answer) caches it again, and every read that is not `ready` drops it.
12. **Pre-connect on resume.** Every ready detail also records the box's origin as its _last
    known origin_, which a lifecycle call does not drop. `resume` (and `start`), while its
    `POST /sandbox/:id/resume` is in flight, opens a connection to that origin on the client's
    own pool: one `GET <origin>/healthz` with no `Authorization`, its body read so the
    connection goes back to the pool, so the first box call after the resume skips the TCP
    and TLS round trips (the box's host terminates TLS and serves while the box is paused).
    It is never waited for, never retried and has no timer. None is sent for a private box
    or a box this client never saw ready. A resume that fails, or that answers a different
    `baseUrl` (a name cutover, private mode), drops it, and the box is reached the normal
    way. Not a fixture: the fixtures serve one ordered conversation and cannot express a
    request racing another; each SDK unit-tests it (`preconnect` in its test suite).
13. **Streamed create.** `create` sends `Accept: application/x-ndjson, application/json`.
    A control plane that streams answers `200 application/x-ndjson` once the box is placed:
    a first line `{"type":"placed","sandboxId","baseUrl"}`, sent the moment the placement
    commits, and a last line `{"type":"answer","status","headers","body"}`, the answer it
    would have given unstreamed. The `placed` line is informational: the SDK MUST NOT resolve
    or connect to its `baseUrl` before the final answer. That origin is handed out before its
    DNS record is known to exist, and an early lookup caches the wrong answer: the zone's
    black-hole wildcard (`*.zbox.sh` answers `192.0.2.1` / `100::` for a name with no
    record) or the NXDOMAIN, for the zone's 1800 s SOA minimum. The box's origin is the
    `baseUrl` of the final answer. The `answer` line is read as the
    response it stands for: its `status`, `headers` (`Retry-After`, `X-Request-Id`,
    `Server-Timing`) and JSON `body` go through the same success, error and retry rules as an
    unstreamed answer. Any other response (every refusal, a replayed create, a server that
    does not stream) is read as it is. A stream that ends before its `answer` line is a
    retryable `unavailable`, like a dropped connection: the retry sends the same
    `Idempotency-Key` and gets the same box. Fixtures `sandboxes_create_streamed` and
    `sandboxes_create_streamed_error` cover the reading (their placed origin is `{{DEAD}}`,
    so a connection to it would never reach the mock); each SDK unit-tests that nothing
    reaches the placed origin (`claimstream` / `claim_stream` in its test suite).

## Box envelope vector

`vectors/box_envelope.json` is a fixed-ephemeral-key vector. Every SDK seals its `plaintext` to
`recipient.agentPublicKey` under `info` with `ephemeral.privateKeyHex` and `iv` in place of
fresh randomness, and must reproduce `envelope` byte for byte. It also opens `envelope` with the
recipient key (a round trip through the same construction as the microvmd opener) and must fail
to open it under `wrongInfo`. `apps/microvmd/test/helpers/BoxEnvelopeVector.test.ts` opens the
same vector with the real guest opener, so a vector that drifts from the box fails CI there too.
